# CLAUDE.md

Правила работы в этом репозитории. Читается первым в каждой сессии.

**Что это за проект.** `audiobook` — локальный пайплайн синтеза аудиокниги с клонированием голоса автора. Разработка на Mac (Apple Silicon), рендер на Ryzen 7 (Ubuntu, CPU). Подробности: `PROJECT.md`. Порядок работ: `PLAN.md`. Переезд на Ryzen: `RYZEN.md`.

**Mac — только тесты.** На Mac запускаются `pytest`, `doctor`, короткий `bench` и одиночные экспериментальные чанки. Никакого пакетного рендера на Mac. Весь рендер книги — на Ryzen.

---

## Команды

```bash
uv sync --extra dev            # установка
./run.sh doctor                # диагностика окружения (Windows: run.bat doctor)
./run.sh doctor --no-models    # то же без проверки весов, для CI
./run.sh bench                 # замер RTF
uv run pytest -q               # слои 1-2, без моделей, секунды
RUN_SLOW=1 uv run pytest -m slow   # слой 3, реальные модели, локально
AUDIOBOOK_DEVICE=cpu ./run.sh ...  # репетиция Windows на Mac
```

Перед завершением любой задачи: `uv run pytest -q` должен быть зелёным.

## Жёсткие правила кода

Их проверяют greptest'ы в `tests/test_portability.py`. Нарушение = красный CI, а не замечание в ревью.

1. **Каждый `open()` с `encoding="utf-8"`.** Windows по умолчанию cp1251, кириллица развалится молча.
2. **Только `pathlib`.** Никакого `os.path.join`, никакой склейки путей строками, никаких `/` в литералах путей.
3. **Никаких обращений к `~/.cache`, `~/Library`, `%APPDATA%`.** Все пути — через `src/audiobook/paths.py`, всё тяжёлое внутри папки проекта (`models/`, `bin/`, `ref/`, `cache/`, `out/`). Переезд должен быть копированием папки.
4. **`ffmpeg` — только через `paths.ffmpeg()`**, который ищет сначала в `bin/`, потом в PATH. Не вызывать `"ffmpeg"` строкой.
5. **Мультипроцессинг под `spawn`.** Всё, что уходит в воркер, должно быть picklable; вход в программу под `if __name__ == "__main__"`. `fork` на Mac работает, на Windows нет — тесты форсируют `spawn`.
6. **Рантайм без сети.** `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`. Скачивание весов — только явным отдельным действием, описанным в README, никогда не мимоходом внутри модуля.
7. **Никаких абсолютных путей и имён пользователя** в коде, конфигах и тестах.

## Инварианты пайплайна

- **Хеш чанка** = `sha1(текст + модель + seed + параметры генерации + хеш файла латентов + переозвучка из pronounce.yaml, если сработала)`. Меняешь состав хеша — обнуляешь весь кеш. Это допустимо, но должно быть осознанным и упомянутым в ответе. Запись в `text/pronounce.yaml` входит в хеш только тех чанков, где реально сработала — остальные сохраняют кеш.
- **Кеш — источник возобновляемости.** Любой шаг синтеза обязан быть перезапускаемым после падения без потери сделанного. Не ломать: не писать в файл кеша частично, писать во временный и переименовывать.
- **Конфиг определяет звук.** Референс, seed, модель, паузы, цели мастеринга — в `config.yaml`, не в коде и не в аргументах по умолчанию.
- **Правится текст, а не аудио.** `read_rules.yaml`, словарь исключений и `chNN.acc.txt` — человеческие артефакты в git. Аудио всегда пересобирается из них. Не делать «постобработку звука вместо правки текста».
- **Латенты референса считаются один раз** и лежат в `ref/`. Не пересчитывать на каждый чанк.
- **CER считается на нормализованных строках** (ударения сняты, ё→е, нижний регистр, без пунктуации, числа в одном виде). Не сравнивать сырые строки — будет лавина ложных срабатываний.

## Тесты

Новый модуль = новые тесты слоя 1 в том же коммите. Слои:

- **Слой 1** — логика и переносимость, без моделей, секунды. В CI на обеих ОС.
- **Слой 2** — имитация Windows на Mac: подменённый `HOME` (после теста проверяется, что туда ничего не записалось), `spawn`, оффлайн, `cpu`.
- **Слой 3** — реальные модели, маркер `slow`, только при `RUN_SLOW=1`. Не в CI.

Тесты не должны ходить в сеть, писать вне `tmp_path` и требовать весов, если не помечены `slow`.

## Чего не делать

- **Не коммитить** `models/`, `ref/`, `cache/`, `out/`, `.env`, веса, аудио. Голос автора и рукопись в публичный репозиторий не попадают ни при каких условиях.
- **Не выдумывать текст книги.** Тестовые и бенчмарочные фразы — плейсхолдеры, не цитаты. Если для задачи нужен реальный фрагмент рукописи — спросить, а не сочинить похожий. Это правило проекта, не стилистическое пожелание.
- **Не менять референс, seed или модель** по своей инициативе после начала рендера — это обнуляет кеш и разъезжает тембр между главами.
- **Не «допишу под Windows потом».** Код пишется переносимым сразу.
- **Не глушить падение синтеза** пустым wav или тишиной. Упавший чанк должен остаться незакешированным и попасть в очередь.
- **Не добавлять зависимости** без явного обсуждения: `uv.lock` должен резолвиться на Windows, а конфликт transformers между `coqui-tts` и `ruaccent` — известная больная точка.
- **Никогда не удалять отрендеренное аудио вручную.** Устаревшие wav выводятся из оборота только механизмом rehash/orphan: при изменении текста или параметров chunker пересчитывает хеши, старые wav становятся orphan и убираются автоматически. Ручное удаление через glob или скрипт — запрещено. Если кажется, что нужно удалить файл руками — остановиться и спросить.
- **Никакого рендера книги без явного разрешения.** `./run.sh chunk` и `./run.sh synth` на всех секциях запускаются только после того, как пользователь явно сказал «настройки зафиксированы, запускай». Любое незакрытое решение — crossfade, split-правило, rolling-контекст, новая запись в pronounce.yaml — означает, что конфиг не заморожен. Прототипы и эксперименты рендерятся на конкретных чанках, не книгой целиком.

## unitmap.py — SectionMap construction rules

`SectionMap` (defined in `src/audiobook/unitmap.py`) may only be created by `map_section()`.

- **Direct construction** (`SectionMap(...)`) outside `unitmap.py` is prohibited.
- **`dataclasses.replace()`** on a `SectionMap` instance, in any file that imports `unitmap`, is prohibited.
- Imports for type annotations are allowed only under `if TYPE_CHECKING:`.

These rules are enforced by AST guard tests in `tests/test_unitmap_spans.py`.

## INVENTORY_ALGO_VERSION bump rules

`INVENTORY_ALGO_VERSION` в `src/audiobook/stress_fp.py` определяет версию алгоритма инвентаря ударений.
Увеличить на 1 при изменении:
- логики определения границ параграфов (разделитель space/`\n\n`);
- критериев классификации форм (top/homograph/name/dict);
- набора колонок в `risk.tsv` или `omographs.tsv`;
- схемы `summary.json` (добавление/удаление полей).

**История версий:**
- v1 — baseline.
- v2 — first unit-based classification (I1/I2/I3).
- v3 (T15) — классификация границ параграфов использует идентичность source unit и kind чанков (`is_within_para`), а не только длительность паузы; 29 граней корпуса теперь классифицируются иначе. Zero-token чанки требуют строгого I2′-матчинга (M1/M2 по NFC+ws). Добавлено поле `zero_token_chunks` в `summary.diagnostics`.
- v5 (T15-7 WP-3) — добавлены advisory `occurrences.tsv`, fingerprints и проверка целого поколения; исторические TSV сохраняют байты v4.

При повышении обновить константу в `stress_fp.py` и дописать в коммит-сообщение `algo_version: N → N+1`.

## Стиль

- Код, имена, комментарии — английский. Вывод CLI, сообщения `doctor`, документы — русский.
- Вывод `doctor` — построчно GREEN/RED по каждому пункту переезда, без абзацев прозы.
- Модули маленькие и отдельные: `chunker`, `synth`, `qc`, `assemble`, `master` не знают друг о друге, общаются через файлы.
- Замена TTS-модели должна затрагивать один модуль. Если приходится править три — архитектура поехала, остановиться и сказать об этом.

## Как отвечать

- Сначала спросить, если задача допускает два прочтения. Уточняющий вопрос дешевле переделки.
- Не сообщать о готовности того, что не запускалось. «Написал, но не проверял» — это так и говорится.
- Если предложенное решение имеет неочевидный минус — назвать его сразу, а не после внедрения.

## Агенты и доска задач

- Задачи — в `tasks/` (протокол в `tasks/README.md`). Агент берёт задачу сменой
  `status`, работает в своей ветке `task/Txx`, сдаёт со `status: review`.
- **В `main` не пушить никогда.** Рабочая ветка — `port-validated-settings`.
- **Вывод команд — дословно.** Свои выводы — отдельным абзацем «Заметки агента»,
  не вместо вывода. Не считать «ok 6/15» по эвристике как результат проверки.
- **Не придумывать команды.** Только то, что есть в `./run.sh <cmd> --help`.
- **Код на gamebox — только через git** (`git pull`), не копированием файлов.
- Перед любой работой на gamebox — `./run.sh preflight` (когда появится; до тех пор —
  ресурсы, `git status`, `pytest`, `doctor`).
- `AUDIOBOOK_CONFIG=<копия>` — только для A/B-проб на копии конфига, никогда для рендера книги.
