## Отчёт

**PASS** на существующем корпусе. Основа реализации:
`2297c8ff764a141d45d5bd7e2e4252b26c1dfe39`.

`stress_inventory` читает неизменённые units и manifest, вызывает `map_section()`
и использует сохранённые Atom/ChunkSpan для paragraph boundaries и diagnostics.
Legacy `annotate_units()`, substring search, tolerant/normalized anchors и
synthesis text preparation не вызываются. Ошибки mapper блокируют inventory;
сообщения содержат только section/chunk identifiers и структурированные коды.
Тексты ошибочных атомов не выводятся.

Для multi-unit chunks граница между chunks определяется adjoining source atoms;
полный набор unit_ids хранится в SectionMap. Существующее scalar-поле unit_id
в zero-Cyrillic diagnostic указывает на первый source unit. Поля TSV и структура
summary.json сохранены, schema_version остаётся 1. Алгоритм поднят **3 → 4**:
смена source mapping и логики multi-unit boundaries должна инвалидировать старую
inventory fingerprint, не synthesis cache. Chunk hashes и audio/cache не менялись.

### Воспроизводимый read-only аудит


Exit code 0 только при PASS; при mapping/input/checksum failure — 1.
Команда ничего не записывает в corpus/inventory, не вызывает RUAccent,
chunk building, normalization, joins command или synthesis. JSON выводится в stdout;
shell redirect записывает только сам отчёт. Отчёт не содержит текстов рукописи.
