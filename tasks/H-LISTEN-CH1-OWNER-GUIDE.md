# Инструкция по прослушке: Глава 1

**Тип:** инструкция владельца. Текст книги, голос, wav-файлы — не в git.
**Когда:** применимо как к частичному превью (`preview_first89.mp3`, ~11 минут, чанки 0001–0089),
так и к полностью отрендеренному разделу с актуальным `section.mp3`.

> **Важно:** `preview_first89.mp3` — это черновой монтаж первых 89 чанков, собранный
> вручную на промежуточном этапе рендера. Он **не равен** итоговому `section.mp3`
> (нет QC-прохода, громкость не выровнена loudnorm, мастеринга нет). Слушать для
> первичной оценки голоса и произношения — **да**; принимать решение о релизе — только
> после финального `master`.

---

## Что нужно проверить при прослушке

Три класса ошибок, которые ловит человек (CER-прогон ловит пропущенные слова, не это):

1. **Ударение** — неверное ударение, которого нет в `pronounce.yaml`. Пример: «Оотзывы» вместо «Отзывы».
2. **Акцент / просодия** — неестественный ритм, странная интонация в конце фразы, слишком ровное или слишком монотонное прочтение.
3. **Артефакт** — щелчок, обрыв, резкое начало или конец фрагмента.

## Слушаем preview_first89.mp3 (частичный превью)

Если полный рендер главы ещё не готов, но `preview_first89.mp3` уже скопирован на Mac:

1. Открыть файл в любом плеере; он **не требует** `review.html` или wav-папки.
2. Слушать последовательно, делать заметки **с таймкодами** (мм:сс):
   - `0:35 — ударение «нАвык» вместо «навЫк»`
   - `2:10 — резкий обрыв в конце фразы`
3. Записывать заметки в любой текстовый файл или блокнот; формальный импорт в
   `labels.yaml` будет по финальному render, не по превью.

> Чанки 0090 и далее в `preview_first89.mp3` **отсутствуют**. Для слушки чанка 0125
> нужен отдельный клип — см. раздел ниже.

## Получить и прослушать чанк 0125 отдельно

Чанк 0125 находится за пределами превью (чанки 0001–0089). Скопировать его вручную:

```bash
# На Mac (dry-run сначала):
rsync -n gamebox:audiobook/out/sections/08_glava_1_zver_vnutri_nas_instinkty_eto_ne/chunks/0125.wav \
  ~/Downloads/audiobook/ch1-clips/

# Если устраивает вывод, убрать -n:
rsync gamebox:audiobook/out/sections/08_glava_1_zver_vnutri_nas_instinkty_eto_ne/chunks/0125.wav \
  ~/Downloads/audiobook/ch1-clips/
```

> Имя раздела уточнить командой `./run.sh status` на gamebox — slug указан в первом столбце.

Прослушать `~/Downloads/audiobook/ch1-clips/0125.wav` и зафиксировать решение одним из вариантов:

| Оценка | Действие |
|---|---|
| **Хорошо** — чанк принят | Ничего не делать; запись пойдёт в финальную сборку |
| **Плохо — ударение** | Добавить слово в `text/pronounce.yaml` по правилу (см. Шаг 6 ниже) |
| **Плохо — артефакт / просодия** | Сделать redo вручную после финального рендера: `./run.sh fix plan`, затем `fix queue` → `queue run` → `fix review` → `accept` |
| **?** | Оставить заметку с таймкодом; вернуться при прослушке через `review.html` |

## Шаг 1 — Создать план прослушки на gamebox

```bash
# Узнать slug главы 1 (первый синтезируемый раздел после вступлений):
./run.sh status | grep -v skip | head -5

# Поставить имя в переменную, например:
export S=08_glava_1_zver_vnutri_nas_instinkty_eto_ne   # уточнить по status

./run.sh listen-plan --section $S --random 10
```

> Не использовать `--notify` (не нужна Telegram-отправка при локальной работе).

Вывод: `план прослушки: N фрагментов, M:SS` и путь `out/listen/plan.mp3`.

---

## Шаг 2 — Перенести на Mac

```bash
# На Mac (--with-wav listen/ch1-local — только wav для страницы разметки):
scripts/mac/fetch_results.sh gamebox --with-wav listen/ch1-local
```

> `fetch_results.sh` без `--with-wav` копирует `*.mp3 *.tsv *.html *.json *.log *.md *.txt`
> из всего `out/`. Для одного превью MP3 предпочтительнее точечный rsync:
> ```bash
> rsync -n gamebox:audiobook/out/sections/08_.../section.mp3 ~/Downloads/audiobook/ch1-local/
> # убедиться в выводе dry-run, убрать -n и повторить
> ```

Файлы в `~/Downloads/audiobook/<ГГГГ-ММ-ДД>/listen/ch1-local/`:
- `plan.mp3` — все фрагменты подряд, 0.8 с между ними
- `index.tsv` — оглавление: время, секция, чанк, теги, текст
- `review.html` — интерактивная страница разметки (офлайн)
- `chunks/*.wav` — wav-файлы, на которые ссылается `review.html`

> `review.html` ссылается на `chunks/<hash16>.wav` по относительному пути.
> Открывать файл **в той папке, где он лежит**, — тогда плеер найдёт wav.

## Шаг 3 — Прослушать и разметить

Открыть `review.html` двойным кликом (работает офлайн, без интернета).

Для каждого фрагмента:
- **хорошо** — всё в порядке
- **плохо** — есть дефект. Выбрать в выпадающем меню: *ударение / акцент / каша / темп / артефакт / другое*. В поле «комментарий» — что именно: «ударение на первом слоге», «резкое начало», «слишком быстро».
- **?** — не уверен, переслушать позже

Подсказки к тегам в оглавлении:
- `начало` — первые 30 с главы
- `подозр: слово` — CER-подозрения по конкретному слову
- `выборка` — случайная проба

## Шаг 4 — Экспортировать и импортировать разметку

На странице: **«Скачать разметку»** → сохраняет `labels_<название>_<id>.json`.

Если кнопка не работает (file://): **«Копировать JSON»** → вставить в файл.

```bash
# На gamebox (или Mac, если журнал там):
./run.sh labels import ~/Downloads/audiobook/<ГГГГ-ММ-ДД>/listen/labels_*.json
# → "добавлено N, уже были M, без оценки K"

./run.sh labels show --section $S   # проверка: таблица с оценками
```

---

## Шаг 5 — Построить план исправлений

```bash
./run.sh fix plan --journal   # читает text/labels.yaml
# вывод: список чанков с "плохо", отсортированных по манифесту
```

Если план не пуст (только когда полный рендер главы завершён и `section.mp3` актуален):
```bash
./run.sh fix queue            # поставить redo в очередь (по 3 кандидата)
./run.sh queue run            # выполнить синтез кандидатов
./run.sh fix review           # страница выбора кандидата (офлайн, открыть двойным кликом)

# После прослушки review.html выбрать лучший вариант N:
./run.sh accept $S <chunk_id> <N>   # N — номер redo-варианта (1, 2, 3, ...)
```

> `fix queue` и `queue run` **не запускать** пока рендер главы не завершён — очередь
> запускает синтез немедленно и пересечётся с основным прогоном.

---

## Шаг 6 — Исправить ударения

Если проблема — ударение, его правят **не переозвучкой, а словарём**:

```bash
# Открыть text/pronounce.yaml и добавить строку по правилу:
# - ключ: слово в том регистре, в каком оно стоит в тексте чанка
# - значение: слово с ударением (одна заглавная ударная гласная: волнУ, ЗапИть)
# - исключение — ударение на первой букве уже-заглавного: Оотзывы
```

После правки `pronounce.yaml`:
```bash
./run.sh chunk --section $S   # 0 queued — хеши пересчитаны, wav не тронуты
./run.sh synth --section $S   # только затронутые чанки
./run.sh assemble --section $S
./run.sh master --section $S
```

## Итого: что приносит один сеанс прослушки

| Команда на gamebox | Результат |
|---|---|
| `listen-plan --section $S` | `out/listen/plan.mp3` + `index.tsv` |
| `fetch_results.sh --with-wav listen` | Файлы на Mac |
| *(разметка в браузере)* | `labels_*.json` |
| `labels import` | Запись в `text/labels.yaml` |
| `fix plan --journal` | `out/fix/plan.json` |
| `fix queue` + `queue run` | Новые кандидаты в `out/redo/` |
| `fix review` → `accept` | Принятый вариант |
| `assemble` + `master` | Обновлённый `section.mp3` |

**Ориентир:** 56 чанков главы × ~3 с на фрагмент = ~3 минуты прослушки на одну главу (с выборкой из 10 фрагментов, `--random 10`). Первый сеанс лучше слушать целиком (`plan.mp3`) перед разметкой.

**Частичный превью vs финальный рендер:**

| | `preview_first89.mp3` | `section.mp3` (финальный) |
|---|---|---|
| Чанки | 0001–0089 (~11 мин) | все чанки главы |
| QC (CER) | не прогонялся | прогонялся, статусы в манифесте |
| Мастеринг | нет | loudnorm −19 LUFS / −3 dBTP |
| Для чего | оценка голоса и произношения | финальная приёмка, `fix plan` |
| Чанк 0125 | **отсутствует** | есть, в `section.mp3` и в `out/sections/.../chunks/0125.wav` |
