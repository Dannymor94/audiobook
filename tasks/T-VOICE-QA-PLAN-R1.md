# VOICE-QA-PLAN-R1 — локальный план исправлений голоса

Связь: Issue #34 (VOICE-QA-01). База: port-validated-settings, 0367704.
Статус: review; применяется только в изолированном локальном checkout.
Владелец технической задачи: ChatGPT (GitHub); Claude Code — только локальный оператор.
Не изменяет production config, pronounce.yaml, рукопись, cache, WAV или manifest.
Новая механика не подключена к рендеру; вызов явный. Хеш по умолчанию прежний.

## Команды (после получения кода из ветки, с локальными данными)

```bash
./run.sh voice-plan --help
./run.sh voice-plan --section SECTION --tag baseline
./run.sh voice-plan --section SECTION --sentence-ms 500 --paragraph-ms 1200 --heading-ms 2200 --tag pause_trial
./run.sh voice-plan --section SECTION --rules PRIVATE_RULES_JSON --tag stress_trial
```

SECTION — точный идентификатор секции с существующим актуальным манифестом.
PRIVATE_RULES_JSON — локальный JSON-объект точных, вручную предложенных замен.
Синтетический пример формата: {"на полку": "на пОлку"}.
Не добавлять туда сырой RUAccent +, SSML, неоднозначные автоматические замены или
личные данные в git. Оценка плана не означает принятие произношения.
Кандидат наследует существующий словарь, переопределяя только указанные ключи;
используется существующий одношаговый longest-first whole-word respell.
План одной секции НЕ разрешает глобальное изменение словаря: требуется проверка
влияния по всем секциям перед применением правила.

## Отчёт

Локальный игнорируемый out/voice_plan/SECTION/TAG.json. Новый тег для нового запуска.
Исходная структура воспроизводится через существующий chunker. Привязка:
порядковый номер нормализованной единицы, SHA256 единицы/секции, точные offsets
в символах Python (end exclusive), последовательное потребление токенов без
глобального поиска фразы. В этой базе не подменяем отсутствующий SectionMap
выдуманным UID. Повтор одинакового текста различается порядком.
Манифест должен полностью совпасть по id, n, text, hash, seed, leadin,
open_end, cont, pause_after_ms; устаревший план блокируется.

Роли: chapter_number, heading_label, chapter_title, chapter_heading_combined,
heading, step_label, list_item, question, narration. Пограничные типы основаны
на структуре и пунктуации. Это карта намерений, НЕ управление голосом Qwen.
Паузы после предложений/абзацев и заголовков 1 уровня задаёт оператор; профиль
by_end и другие настройки сохраняются. Не меняется речь внутри WAV.
Применять карты/настраивать интонацию модели автоматически запрещено.

- pause_only — хеш и подготовленный вход неизменны, пауза отличается.
- needs_synth — новый хеш, потенциальная потеря кеша; указан locked/status.
- review_only — хеш и паузы совпали; в том числе подсказки интонации.
- blocked_hash_gap — подготовленный вход модели изменился, но хеш прежний.
  Это важно при словарной замене в контекстном lead-in или через его границу.
  В этом случае весь план BLOCKED (exit 2), даже если собственный текст
  другого чанка корректно меняет свой хеш. Не использовать для рендера.
  Нужен адресный фикс контракта кеша, не массовое обнуление.

Счётчики попаданий новых правил включают lead-in; это не точное число
произнесённых слов. Режим enum_pause_ms != 0 блокируется, поскольку там
другая траектория подготовки фрагментов. Сравнение полного padded input
до неизменного sentinel — не обещание правильного произношения.
