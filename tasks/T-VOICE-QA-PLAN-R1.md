## Обязательный протокол передачи задач агентам

Координатор всегда выдаёт владельцу готовый копируемый промпт для конкретного
агента, если для следующего шага требуется его участие. Это обязательное
правило владельца от 24.11.2026.
Если полная спецификация уже опубликована, промпт содержит точную ссылку
на Issue/комментарий/PR или путь к файлу с заданием, роль, название задачи,
действие, ожидаемый результат и стоп-условие. Не дублировать длинную
спецификацию. Промпты агентам — на английском, общение с владельцем — на русском.
Исполнителя обозначать по роли и названию задачи, а не номером агента.
Публикация задания в GitHub сама по себе не считается запуском локального агента.
Если внешнее участие не нужно, координатор выполняет доступную работу сам.

## GitHub-first — единый журнал проекта

Обязательное решение владельца от 24.11.2026. Вся рабочая деятельность
координатора и агентов отражается в GitHub: планы, задания, исполнители,
статусы, изменения, подробные отчёты, результаты тестов/CI, ревью, решения,
блокеры, передача следующему исполнителю. Не вести параллельные журналы в чатах.

- Issue — постановка задачи, статус, подробный отчёт и операционные решения.
- PR — изменения кода, точный SHA, тесты, результаты CI, замечания ревью.
- Документы/файлы задач в репозитории — утверждённый план, постоянные правила,
  инструкции и необходимые долговременные записи.
- Перед началом агент читает актуальный Issue/PR, не полагается только на
  скопированный текст промпта. После работы обновляет соответствующую
  существующую задачу; не создаёт дубликаты и не закрывает её самостоятельно,
  если окончательное решение принадлежит координатору/владельцу.
- Подробный отчёт: задача, статус, проверенный SHA/окружение, выполненные
  действия, фактические проверки и результаты, ссылки на PR/CI, ограничения,
  блокеры, следующий шаг. Для каждой проверки отличать реально выполненную
  от запланированной. Дословные безопасные результаты команд — в GitHub.
- В чат агент возвращает только TASK, PASS / FAIL / BLOCKED, ссылку на
  опубликованный отчёт и, если нужно, одно краткое решение/действие владельца.
  Не дублировать подробный отчёт, код, diff, логи и спецификации в чате.
  Координатор сам открывает отчёт по ссылке и проверяет доказательства.
- Приватность выше полноты отчёта: рукопись, отдельные слова из книги,
  приватные словарные TSV, WAV/MP3, секреты, личные пути и чувствительные
  логи остаются локально. В GitHub только обезличенные технические данные,
  безопасные метрики и хеши. Локальные пути для прослушивания — только
  владельцу приватно, без загрузки файлов. Если GitHub недоступен, сохранить
  безопасный отчёт локально и сообщить BLOCKED_REPORT_PUBLICATION, не
  утверждать, что отчёт опубликован.
- Каждый новый промпт агенту содержит требование GitHub-first или точную
  ссылку на этот протокол. В чате координатор также сообщает только
  существенный результат, решение, ссылки и готовый следующий промпт.

## Цель и ответственность

Естественный голос автора, правильные ударения, спокойный темп, смысловые
паузы и выделенные интонацией названия глав. Первая полная глава — эталон.

- ChatGPT: координатор, разработка через GitHub, алгоритмы, тесты, CI,
  ревью, интеграция, безопасность кеша и очереди, документация.
- Claude Code: локальный оператор на Mac, доступ к gamebox по существующему SSH.
  Диагностика реального звука, проверка алгоритмов на локальном тексте,
  короткие образцы, разрешённые изменения и рендер. Не дублировать разработку.
- Владелец: прослушивание, выбор звучания, разрешение production-изменений
  и отдельное разрешение полного рендера.
- Архитектор/независимый QA: только при конкретном существенном нерешённом
  вопросе; без дополнительных циклов ради формальности.

## Команды (после получения кода из ветки, с локальными данными)

```bash
./run.sh voice-plan --help
./run.sh voice-plan --section SECTION --tag baseline
./run.sh voice-plan --section SECTION --sentence-ms 500 --paragraph-ms 1200 --heading-ms 2200 --tag pause_trial
./run.sh voice-plan --section SECTION --rules PRIVATE_RULES_JSON --tag stress_trial
```

SECTION — точный идентификатор секции с существующим актуальным манифестом.
PRIVATE_RULES_JSON — локальный JSON-объект точных, вручную предложенных замен.
Синтетический пример формата: {"на полку": "на пОлку"}.
Не добавлять туда сырой RUAccent +, SSML, неоднозначные автоматические замены или
личные данные в git. Оценка плана не означает принятие произношения.
Кандидат наследует существующий словарь, переопределяя только указанные ключи;
используется существующий одношаговый longest-first whole-word respell.
План одной секции НЕ разрешает глобальное изменение словаря: требуется проверка
влияния по всем секциям перед применением правила.

## Отчёт

Локальный игнорируемый out/voice_plan/SECTION/TAG.json. Новый тег для нового запуска.
Исходная структура воспроизводится через существующий chunker. Привязка:
порядковый номер нормализованной единицы, SHA256 единицы/секции, точные offsets
в символах Python (end exclusive), последовательное потребление токенов без
глобального поиска фразы. В этой базе не подменяем отсутствующий SectionMap
выдуманным UID. Повтор одинакового текста различается порядком.
Манифест должен полностью совпасть по id, n, text, hash, seed, leadin,
open_end, cont, pause_after_ms; устаревший план блокируется.

Роли: chapter_number, heading_label, chapter_title, chapter_heading_combined,
heading, step_label, list_item, question, narration. Пограничные типы основаны
на структуре и пунктуации. Это карта намерений, НЕ управление голосом Qwen.
Паузы после предложений/абзацев и заголовков 1 уровня задаёт оператор; профиль
by_end и другие настройки сохраняются. Не меняется речь внутри WAV.
Применять карты/настраивать интонацию модели автоматически запрещено.

- pause_only — хеш и подготовленный вход неизменны, пауза отличается.
- needs_synth — новый хеш, потенциальная потеря кеша; указан locked/status.
- review_only — хеш и паузы совпали; в том числе подсказки интонации.
- blocked_hash_gap — подготовленный вход модели изменился, но хеш прежний.
  Это важно при словарной замене в контекстном lead-in или через его границу.
  В этом случае весь план BLOCKED (exit 2), даже если собственный текст
  другого чанка корректно меняет свой хеш. Не использовать для рендера.
  Нужен адресный фикс контракта кеша, не массовое обнуление.

Счётчики попаданий новых правил включают lead-in; это не точное число
произнесённых слов. Режим enum_pause_ms != 0 блокируется, поскольку там
другая траектория подготовки фрагментов. Сравнение полного padded input
до неизменного sentinel — не обещание правильного произношения.
