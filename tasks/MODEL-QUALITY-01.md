### Заметки агента: три оставшихся риска

1. **Оборванная синтаксическая вводная.** `leadin.py:69–89` при длинном
   предложении берёт последние слова в пределах 60 символов. Предыдущий
   контекст уже включён; новая гипотеза — восстановить целое предложение
   длиной 61–80 символов, изменив только лимит. Возможный эффект — более
   связная интонация/тембр; цена — дополнительный синтез и риск обрезки
   более длинной вводной. Вне затронутого контекста hash не меняется.
   G12 проверял off/previous на главе 13, а не этот лимит на главе 1.
2. **Контекстные омографы/неверное ударение при хорошем CER.** `yo.py`
   намеренно исключает омографы; `qc.py` снимает ударения и сводит ё к е.
   CER не доказывает правильное ударение, а низкая уверенность Whisper не
   доказывает дефект TTS. Существующий pronounce/fix достаточен для
   подтверждённых слухом случаев; новой универсальной правки не предлагается.
   G18 уже занимается известным случаем в главе 13 — не дублировать.
3. **Начало слова после удаления вводной.** `leadin.py:185–213` использует
   timestamp выровненного слова; DP допускает замену вместо точного совпадения.
   Синтетическая подмена первого собственного слова проходит выравнивание.
   Это риск локализации границы, не доказанный акустический дефект/P0.
   При жалобе различать TTS, обрезку вводной и `_trim_bounds` в assemble;
   loudnorm/монтаж также не объяснять моделью без сравнения исходного чанка.
   В этом цикле алгоритмы обрезки не менять.

### SFT_FEASIBILITY

Официальный upstream на момент проверки: `022e286b98fbec7e1e916cb940cdf532cd9f488e`.
[README](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/finetuning/README.md)
поддерживает single-speaker SFT для Base: локальные JSONL `audio`, `text`,
`ref_audio`, затем tokenizer извлекает `audio_codes`; один ref для всех примеров
рекомендован для стабильности. Минимальные часы, длина сегментов и VRAM не указаны.

Инженерная рекомендация, не гарантия upstream: авторские записи с согласием,
чистые законченные реплики без музыки/перекрытий/срезанных фонем; расшифровка
дословно по аудио, не исходная рукопись вместо реально произнесённого текста.
Проверить слова, числа, ё, паузы и соответствие каждой пары; удалить дубли,
разделить train/holdout по сессиям, не соседним фрагментам. Данных не читал,
достаточность доступной записи неизвестна.

[dataset.py](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/finetuning/dataset.py)
требует 24 kHz для reference mel. Код не подтверждает произвольную длительность
или автоматическое исправление расшифровки.
[sft_12hz.py](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/finetuning/sft_12hz.py)
использует BF16/FlashAttention2, Accelerator, AdamW по параметрам модели и
gradient accumulation=4. Это не готовый LoRA/CPU-рецепт. Оценка порядка памяти
для 1.7B: bf16 веса+градиенты и fp32 Adam moments ≈20.4 GB до активаций,
буферов и возможных master weights; не обещание, что 24 GB достаточно.
Для планирования разумен локальный CUDA GPU с 40–48 GB и подбором batch/длины,
но это непроверенный бюджет, не официальный минимум. Наличие такой свободной
карты не установлено; Ryzen CPU нецелесообразен для этого upstream-рецепта.
README даёт разные примеры batch/lr/epochs — их нельзя считать доказанным
рецептом именно для русского авторского голоса.

Обучение может закрепить акцент/ошибки, переобучить голос и ухудшить сходство
или просодию. Код сохраняет custom_voice checkpoint и пример вызывает
generate_custom_voice; текущий адаптер вызывает generate_voice_clone с ICL.
Это будущая отдельная интеграция/идентичность модели, не бесшовная настройка.
Нужны pin upstream/weights/tokenizer/dependencies, seed/data order, split,
hyperparameters и checkpoint SHA. Обучение/подготовка данных только локально,
offline с локальными весами и без remote logging; private wav/transcripts,
codes, speaker embedding, logs и checkpoints не публиковать. Сейчас обучение
не осуществимо в разрешённых рамках и не рекомендуется для production.
