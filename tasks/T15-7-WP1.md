## Internal milestone A — 7.1a: Immutable local baseline

Implement `tests/helpers/t15_7_fixture.py` and synthetic S1 data under the allowed paths.

- Capture from production's existing *pure preparation* functions, without calling the synthesis engine, in both normal and enumeration modes. Preserve exact order and identity: `section`, `row["id"]`, `fragment:int|null`.
- For each SU, capture SHA-256 of the **actual final text that would be passed to the engine**, with `phrase_sha256 = null` if the carrier is None, and SHA-256 of empty string if `phrase=""`. Distinguish these values byte-for-byte.
- Record the stored manifest chunk hashes, the analytic manifest fields listed in the ADR, the **actual** result/error class of read-only `ensure_manifest_current()`, and the **actual** read-only impact value. Never assume freshness or `impact=0`.
- Write real-corpus baseline fixtures only to ignored `out/t15_7/baseline/`; use canonical deterministic UTF-8 serialization. Compute aggregate digest `D = SHA256` of the canonical baseline fixture bytes. The output to console/report is aggregate D/counts/status only.
- Provide an explicit `--check` operation that compares the locally recalculated fixture/digest to the frozen stored baseline without modifying it.
- Use an independent synthetic literal oracle with `enum_pause_ms>0` and enum fragments, so the unexercised production branch is checked without introducing real manuscript text.
- If capture cannot reconstruct the same SU set without duplicating production logic, or running a required function would write to production `out/`, cache, manifests or call a model, **STOP** before implementation of 7.2.

**Internal gate A (mandatory before B):** `--check` reproduces D and counts, synthetic enum test passes, no S2 leaks, no changes to existing synthesis files, focused tests pass. Capture the exact baseline SHA for later verification. This is a self-check by Sonnet; NO intermediate Sol review.

## Internal milestone B — 7.2: Observational SUTrace

Implement only `src/audiobook/sutrace.py` and `tests/test_sutrace.py`, using the existing functions/semantics discovered in 7.0d.

- Expose ADR-required `SUTrace(section, chunk_id, fragment, prep_text, pad_len, matches, final_sha256, phrase_sha256, status)` and `trace_section()` (exact signatures per ADR/actual API). Do not change the synthesizer to import or invoke this module.
- Record (do not reapply differently) the normal and enum-fragment preparation path: `voicecfg.prepare_text`, lead-in selection/padding, `pronounce.respell`, sentinel insertion. For enum fragments, preserve production's question-mark stripping, AUTO lead-in and fragment indexes.
- Record pronunciation-rule matches by reusing existing `pronounce.build_pattern` and `respell` semantics; no regex reinterpretation, blind substring search, heuristic word alignment or duplicate transformation implementation.
- `pad_len` is the length difference before respell after verifying the padded value ends with prepared text. `phrase=None` and empty carrier must preserve separate `phrase_sha256` identities.
- Add key-recording guards so the set of accessed config keys is a subset of the declared keys from ADR; fail closed on unexpected dependencies.
- Verify all SUs from the existing frozen snapshot against the milestone-A baseline: exact SU set and IDs, final/phrase SHA values, stored chunk hashes, analytic manifest fields, freshness and impact equivalence. Baseline is the source of comparison; do not change it to make tests pass.
- Include tests for standard, enum, missing optional manifest fields, deterministic hashes and NONE-vs-empty carrier. AST guard: `synth`, `worker`, `voicecfg`, `pronounce`, `engine` do not import the new module.

**Internal gate B:** focused tests + full `uv run pytest -q` green; baseline `--check` returns identical digest D; unchanged synth input bytes/cache/hash/config; P1/P4 privacy checks; no regression in accepted 6C11.

## STOP conditions

- The current branch/worktree cannot safely be used or protected source files are unexpectedly tracked.
- Baseline cannot be reproduced, or data differs from the existing effective TTS input.
- Any normal or enum SU yields `trace_mismatch`; no silent fallback.
- Any mapping integrity or privacy check fails.
- A new module cannot provide observational trace without modifying production synthesis code or duplicating its business logic.
- Existing code/test expectations contradict the normative ADR and cannot be resolved by a narrow local implementation.
- Full pytest fails, even if new focused tests pass.
- `--check` writes to production data, changes snapshots or mutates cached artifacts.

On STOP, report `BLOCKED` and evidence. Do not broaden scope, regenerate manifests, alter 6C11, create new architecture or silently skip affected rows.
