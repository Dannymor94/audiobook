# Производство аудиокниги — контрольная глава → полный рендер → выпуск

Статус: **операционный план, НЕ разрешение на полный рендер**. База: `port-validated-settings` / `03677041d4fbd06e072529092deaa0e37dc2560f` (2026-11-23).
Источник решения: [CONTROL-RENDER-1 #26](https://github.com/Dannymor94/audiobook/issues/26). Gate C-B/D и WP5 параллельны и не блокируют рендер. Смена модели/референса/seed/temperature, main-merge и доступ к S4 не разрешены.

## 1. Что уже есть — без нового UI

- Очередь: `src/audiobook/jobqueue.py`, `./run.sh queue list`, сервис `scripts/gamebox/audiobook-queue.service`.
- Прогресс: `./run.sh status` (только чтение; прогноз RTF из config, уточняется после реального замера).
- Прослушивание: `./run.sh listen-plan --section <SEC> --tag <TAG>`, затем `./run.sh review --dir out/listen/<TAG>`, `./run.sh labels import <labels_*.json>`, `./run.sh fix plan`. Страница работает локально, сохраняет разметку через браузер; `fix queue` запускает реальные тяжёлые задания и требует отдельного решения.
- Сборка книги: `./run.sh export --format mp3` либо `--format m4b` после готовности всех включённых разделов. **Не использовать `--allow-missing`** для полного выпуска. Обложка опциональна; метаданные берутся из `config.yaml`.

## 2. Пока контрольная глава рендерится

- На `gamebox`: **никаких** дополнительных тяжёлых команд или тестов (включая `bench`, `redo`, `listen-plan`, `export`) параллельно синтезу.
- На отдельном Mac worktree: документация, синтетические pytest, проверка команд и тестов; **не трогать** WP4/S2, `text/stress_gold*`, YO-evidence, TODO, голос, реальные тексты и аудио.
- Не использовать `render_all.sh` (исторический WORKERS=4): продакшен-модель 1.7B допускает не более двух воркеров.
- **Нельзя "заранее поставить" книгу в `out/queue/pending`**: установленный `queue run --watch` сразу подхватывает добавленное. Подготовка списка заданий — только текстовый план/синтетическая проверка.
- Проверить актуальные SHA `config.yaml`, `text/pronounce.yaml`, латентов, HEAD и среду непосредственно перед будущим рендером; не угадывать ID секций или количество читаемых разделов.

## 3. Когда готов MP3 первой главы

1. Проверить `synthesized/skipped/timeout`, длительность, измеренный RTF, QC CER, `assemble/master` и наличие проигрываемого `section.mp3`.
2. Проверить контрольный повтор без изменений (`synthesized=0`) и отдельный файлово изолированный эксперимент с одним правилом `pronounce.yaml`. Git-ветка **не изолирует** игнорируемые `out/` и `cache/`.
3. Забрать контрольный MP3 **только на Mac владельца**. Штатный `scripts/mac/fetch_results.sh gamebox` — **широкая синхронизация всего `out/`**: он также переносит `.json`, `.tsv`, `.log`, `.txt`, `.html` и MP3 других разделов. Если нужен лишь контрольный MP3, использовать ограниченный локальный `rsync` по точному пути `out/sections/<SEC>/section.mp3` после проверки хоста и назначения; лог/личные файлы не копировать. Для интерактивной разметки необходимы соответствующие `out/listen/<TAG>/chunks/*.wav`, `review.html` и `index.tsv`, их можно перенести отдельно, после предварительного `--dry-run`. Указанная передача разрешена **только между своими gamebox и Mac**, не в Telegram/облако/GitHub.
4. Владелец прослушивает всю главу и фиксирует **ACCEPT_AUDIO** или **REJECT_AUDIO**. Только ACCEPT_AUDIO разрешает полную очередь. Нет автоматического перехода по успешному тесту.

## 4. Обозначения ошибок и локальная разметка

Для короткой выборки после готовности MP3 (не во время synth):
```bash
./run.sh listen-plan --section "$SEC" --tag ch1-local
./run.sh review --dir out/listen/ch1-local
```
После локального переноса `out/listen/ch1-local` вместе с WAV-фрагментами из `chunks/` открыть `review.html` на Mac, отметить "хорошо / плохо / ?" и указать причину; сохранить `labels_*.json`. Для подготовки плана:
```bash
./run.sh fix plan /path/to/labels_ch1-local.json
```
**Не вызывать `fix queue` или `queue redo` в рамках подготовки:** они запускают реальный синтез, если служба следит за очередью. Замечания по произношению оформляются только как локальные записи и после одобрения → `pronounce.yaml` → `impact --section` → точечный рендер; ничего не удалять вручную.

## 5. Полный рендер — план, а не выполняемые сейчас команды

После `ACCEPT_AUDIO` владелец отдельно разрешает полноценный рендер. Оператор:
1. Выбирает официальный список и порядок читаемых разделов из `status.book_sections()`, сверяет `render.skip_sections`, живые главы/исключения и правила выпуска. Не считать все разделы автоматически синтезируемыми.
2. Выполняет `./run.sh preflight` и сверяет зафиксированные SHA, доступную память/диск, модель 1.7B и `--workers 2`; проверяет состояние `queue list`, systemd-службы, отсутствие других синтезов.
3. Проверяет, что Telegram-токены/уведомления выключены в **фактической среде службы** (run.sh загружает .env); без этого не отправлять логи, списки слов и аудио. Не запускать `queue section`: этот shortcut добавляет `listen-plan --notify`.
4. Использует `queue add -- chunk/synth --section ...` и последующие `qc/assemble/master` только после проверки ограничений. Важно: **текущий воркер продолжает следующее задание после FAILED**, а значит многокомандная очередь не является fail-fast. Пока это не исправлено/не обойдено проверяемым оркестратором, не разрешать автоматический прогон всего списка без контроля ошибок.
5. Пишет лог выполненных задач, чанк-статусы, фактический RTF и ошибки. При рестарте использует существующий `--requeue-interrupted`, без удаления WAV/кеша и без ручных повторов наугад. Открытые правки произношения измеряет через read-only `./run.sh impact --section "$SEC"` и пересинтезирует лишь затронутое.

## 6. Выпуск

- После получения всех актуальных `section.mp3` проверить список, порядок, заголовки, длительности, уровни громкости и чистоту стыков. `export.py` отказывает при отсутствующих файлах или устаревших MP3 по mtime; **mtime не заменяет** проверку чанков/их хешей и состояния завершения.
- Выполнить `./run.sh export --format mp3` и `./run.sh export --format m4b` **только по готовой книге**. Не использовать `--allow-missing`; финальный файл не отправлять в облако без отдельного разрешения.
- Сохранить SHA итоговых артефактов и результаты выборочного прослушивания, затем запросить решение владельца о публикации.

### Прозрачная оценка производительности

По промежуточному отчёту последнего `synth`: `2654s wall`, `36 synthesized`, `201 skipped`, `1 timeout`, предварительная длительность раздела `1639s`, печатный RTF `11.9x`. `skipped` не означает однозначно reuse; оно включает уже имевшиеся WAV/кеш. Следовательно, `2654/1639≈1.62x` — **не полный cold-render RTF**, а `11.9x` относится к звуку, синтезированному именно за этот запуск. Для ETA всей книги нужен суммарный wall time **всех** заходов синтеза от пустого кеша до готового раздела / фактическая длительность финального MP3, отдельно QC/assemble/master. Если логи ранних заходов отсутствуют, точный cold RTF/ETA остаётся неизвестным.

## Ограничение ответственности

Этот документ не меняет код синтеза, не запускает очередь и не разрешает полный рендер. Проверку реального `gamebox`, публичных статусов и качества MP3 должен подтвердить локальный оператор/владелец; GitHub Actions не имеют доступа к локальным весам, голосу и корпусу.
