# Аудиоверсия книги — описание проекта

**Проект:** `audiobook` — локальный пайплайн синтеза аудиокниги с клонированием голоса автора
**Статус:** пайплайн замкнут end-to-end, один раздел отрендерен; массовый рендер не запускался
**Дата версии:** 19 сентября 2026 (ред. 4)

---

## 1. Цель

Получить аудиоверсию электронной книги, озвученную голосом автора, без облачных сервисов и без оплаты за символы. Разработка, отладка и правка выполняются локально; наружу уходит только финальный массовый рендер, на арендованную GPU-машину.

Аудиоверсия — не самостоятельный продукт, а расширение уже существующего входного продукта воронки. Отсюда требование к качеству: слушатель не должен опознать синтез. Если опознаёт — проект не достиг цели, даже если технически отработал.

## 2. Ограничения

| Ограничение | Следствие |
|---|---|
| Разработка на Mac (Apple Silicon) | Qwen на MPS не работает (кастомный `generate` мешает CPU- и MPS-тензоры) — локально всё считается на CPU. RTF ~6, терпимо для тестов, неприемлемо для книги. |
| Локального GPU нет | RX 580 вне ROCm (Polaris выброшен в ROCm 5.x, DirectML заброшен). Ноутбучная RX 6600M (RDNA2, gfx1032) технически годится через `HSA_OVERRIDE_GFX_VERSION`, но поддержка неофициальная, а на ней Windows. **Массовый рендер — аренда.** |
| Книга — платный продукт | Лицензия модели решает. Qwen3-TTS под Apache 2.0 — вопрос закрыт. |
| Голос принадлежит автору | Письменное согласие на клонирование получено. **Отдельно:** аренда означает выгрузку референса и текста на чужой сервер — это выходит за рамки исходного согласия, уточнить у автора. |
| Объём рукописи | 499 986 знаков, 5127 чанков, ≈13 часов аудио, ~2,3 ГБ сырых кусков. |
| Рукопись содержит невербальные блоки | 102 стрелочные строки, 2 цепочки, 7 многострочных алгоритмов, 6 прозаических блоков со стрелкой, 16 подписей к рисункам. См. §5.1. |

## 3. Архитектурные решения

1. **Один код, две площадки.** Разработка на macOS, рендер на арендованном Linux с CUDA. Переносимость проверяется автоматически: кодировки, `pathlib`, `spawn`, отсутствие домашнего кэша — правила те же, что раньше писались под Windows.
2. **Всё тяжёлое — внутри папки проекта.** Веса, ffmpeg, референс в `models/`, `bin/`, `ref/`.
3. **Куски аудио лежат на диске всегда, в папке своего раздела.** Отдельного кеша по хешу нет. Возобновляемость обеспечивает манифест: хеш совпал и файл на месте → пропускаем. Проверено убийством процесса на середине раздела.
4. **Автоматический контроль качества.** На 13 часах брак руками не найти — сверка ASR-транскрипта с исходником обязательна.
5. **Правится текст, а не аудио.** `read_rules.yaml`, словари и `.norm.txt` — человеческие артефакты в git. Аудио пересобирается из них.
6. **Конфиг определяет звук.** Референс, seed, модель, температура, паузы — в `config.yaml`, он в git и входит в хеш чанка.
7. **Мастеринг обязателен.** Сырой выход Qwen «горячий»: пик 0,991, тру-пик +0,08 dBTP. Без `master` раздел клиппит. Раздел без мастеринга наружу не отдаётся никогда.
8. **Ручная правка — первоклассная операция.** Переозвучить кусок, поправить его произношение, зафиксировать принятое — команды CLI, а не ковыряние в файлах. См. §5.7.

## 4. Стек

**Текстовый слой:**
- RUNorm — числа прописью, аббревиатуры, проценты, диапазоны, порядковые.
- RUAccent — **вне рендер-пути.** `.acc.txt` остаётся артефактом человеческой вычитки омографов, в модель не подаётся.
- `read_rules.yaml` — устные формы невербальных блоков.
- `pronounce.yaml` — словарь произношения: подсказки модели там, где она ставит ударение неверно. Применяется к тексту чанка перед синтезом, книгу не трогает, входит в хеш чанка.

**Вход синтеза — `.norm.txt` с сохранённым «ё».** Проверено на слух: знаки ударения «+» делают речь неразборчивой; «ё» Qwen читает верно, поэтому воркэраунд «ё→е» из эпохи XTTS убран и 314 слов сохранили смысл.

**Синтез:**
- Qwen3-TTS-12Hz-0.6B-Base (`qwen-tts` 0.1.1). **Apache 2.0.**
- Модель обрезает хвост чанка без стоп-сигнала. Митигация: к тексту без финальной пунктуации дописывается sentinel (`model.sentinel`, по умолчанию « .»), срезается при тримминге. Применяется условно — 589 чанкам из 5127.
- Скорости у 0.6B-Base нет; темп задаёт референс (длиннее референс → медленнее речь).
- Модель грузится из локального снапшота, не по repo-id: под `HF_HUB_OFFLINE=1` загрузка по repo-id лезет в сеть и падает.

**Почему не XTTS-v2.** Отклонён после полного цикла проверок. Тембр копировал отлично, читать по-русски не умел: акцент, неверные ударения, роботизация. Причина в токенизаторе — маленький custom-BPE без merge-ей для «ё» и знаков ударения, слова рассыпались на куски. Ни референс, ни темп, ни усреднение латентов этого не лечили.

**QC:** faster-whisper 1.2.1 (CTranslate2, int8, CPU).

**Сборка и мастеринг:** ffmpeg — тримминг тишины, паузы, кроссфейд, highpass, two-pass loudnorm, метаданные.

**Инфраструктура:** Python 3.11, `uv` + lock, pytest, GitHub Actions. Один venv, один `uv sync` — coqui-tts убран целиком, и вместе с ним конфликт transformers, который раньше требовал второго окружения.

## 5. Пайплайн

```
рукопись (text/*.docx, не в git)
 1. extract_blocks          → text/blocks/NN_<slug>.blocks.json
 2. read_rules.yaml         → text/NN_<slug>.txt        ← устные формы, в git
 3. RUNorm + словарь        → text/NN_<slug>.norm.txt   ← ВХОД СИНТЕЗА
    (RUAccent → .acc.txt — вычитка человеком, в рендер не идёт)
 4. chunker                 → out/sections/NN_<slug>/manifest.jsonl
 5. pronounce.yaml + synth  → out/sections/NN_<slug>/chunks/NNNN.wav
 6. qc (faster-whisper)     → статусы в манифесте, ручная очередь
 7. assemble                → out/sections/NN_<slug>/section.wav
 8. master                  → section.mp3 (+ book.m4b по желанию)
```

56 непустых разделов, нумерация по позиции в документе. Slug — транслитерация заголовка. Порядок разделов никогда не берётся из алфавитной сортировки.

### 5.1 Невербальные блоки

| Тип | Кол-во | Действие |
|---|---|---|
| `heading` | 484 | Читается, отдельный чанк. Пауза по уровню: H1 1500 мс, H2 900, H3 и ниже 600 |
| `paragraph` | 4033 | Читается |
| `flow` (→) | 102 | Устная форма из `read_rules.yaml` |
| `chain` (↓) | 2 | Устная форма. `normalize()` склеивает параграф + строку-стрелку + параграф в один блок |
| `stack` | 7 | Читается как есть, пауза 500 мс между строками |
| `prose_with_arrow` | 6 | Абзац остаётся, меняется только фрагмент со стрелкой |
| `figure_caption` | 16 | Skip. Ссылок на рисунки в тексте нет |

Матчинг устных форм — по хешу оригинала. Блок, требующий устной формы и не нашедший её, **валит прогон**, а не пишет предупреждение.

### 5.2 Нормализация текста

- `%` → «процентов» в нужном падеже.
- `–` между словами → `—`; между числами → диапазон.
- Диапазон без предлога → «от N до M»; после предлога → дефисная пара в падеже предлога («до двух-трёх лет»). Два предлога подряд недопустимы.
- Порядковые с суффиксом: `51-я` → «пятьдесят первая».
- Ссылки на главы: «в Главе 12» → «в двенадцатой главе».
- **«Ё» сохраняется.**

**Ассерт на кодпоинты.** `.norm.txt` содержит только буквы, пробелы и обычную пунктуацию. Любой другой символ валит прогон с указанием раздела и строки.

### 5.3 Чанкинг и манифест

120–220 знаков, потолок 250, минимум 40. Абзац — всегда граница. Не рвать внутри кавычек и скобок, не заканчивать на предлоге, союзе или «не». Правило кавычек уступает потолку: выше 250 рвём по границе предложения внутри кавычек.

Медиана 87 знаков — ниже цели, потому что 358 заголовков и 751 короткий абзац атомарны. Слияние соседних коротких абзацев рассмотрено и отклонено: экономия 3% ценой потери 900-мс зазора между абзацами и новой логики в `assemble`.

`manifest.jsonl`, строка на чанк: `id`, `n`, `text`, `hash`, `seed`, `pause_after_ms`, `status`, `locked`, `duration_ms`.

**Выравнивание при переразбиении** по хешу текста: совпал — wav переименовывается, не совпал — в очередь, осиротевшие в `chunks/_orphan/`.

### 5.4 Синтез

- Референс `ref/isaev_ref.wav` (15 с, mono 24 кГц), латенты — speaker x-vector, считаются один раз.
- Хеш чанка: `sha1(текст + модель + seed + параметры + словарь произношения + хеш латентов)`. Смена любого из них инвалидирует всё — необратимо после начала рендера.
- **Seed выводится из хеша чанка**, не фиксирован на книгу: интонация разная, но воспроизводимая при пересборке.
- `temperature` 0.9. Значение из валидированных на слух сэмплов. Высокая температура даёт живость ценой риска, что модель проглотит слово, — это ловит QC.
- Кусок с `locked: true` массовый прогон не трогает.

### 5.5 Контроль качества

Порог CER 5% → переозвучка с другим seed, до 3 попыток, дальше в ручную очередь.

**Сравнение идёт через общий нормализатор:** снять ударения, `ё → е`, нижний регистр, убрать пунктуацию, числа к одному виду. Иначе разные нормализации текста и транскрипта дадут очередь на половину книги.

Отдельно QC ловит то, чего лишились вместе с RUAccent, — неверные ударения. Первый живой случай: заголовок «Отзывы» прочитан как «отзывЫ». Лечится записью в `pronounce.yaml`, не правкой книги.

**Правило дома для коррекции ударения (подтверждено на слух).** Два случая:

1. **По умолчанию — одиночная заглавная ударная гласная:** `волну → волнУ`, `Запить → ЗапИть`. Проверено на ударении в конце слова; применяется всегда, когда ударная гласная не является первой буквой уже-заглавного слова.
2. **Исключение — ударение на первой букве уже-заглавного слова:** удвоение ударной гласной, потому что заглавная там неотличима от обычной капитализации начала слова: `Отзывы → Оотзывы`.

Что проверено и отвергнуто (всё хуже базовой линии): знак ударения (акут U+0301) — игнорируется, звук не меняется; «+» из RUAccent — ломает речь; дефис, пробел, капс всего ударного слога. Удвоение растягивает гласную (2,56 с против 1,52 с), но `sentinel` из `config.model` обрезает этот хвост. Матч в `pronounce.yaml` регистрозависимый и по целому слову — ключ пишется в том регистре, в каком слово стоит в тексте (`Запить` ловит вхождение в начале предложения, строчный ключ не сработал бы).

### 5.6 Сборка и мастеринг

- **Тримминг краёв** до вставки пауз, иначе заданные значения не соблюдаются.
- Паузы: 350 мс между предложениями, 900 в конце абзаца, 500 между строками `stack`, по уровню после заголовка, 2000 в конце раздела. Кроссфейд 20 мс.
- Мастеринг: highpass 80 Гц, two-pass loudnorm −19 LUFS / −3 dBTP, 44.1 кГц. **Обязателен** — см. решение 7.
- Метаданные: ID3v2 для mp3; для `.m4b` — обложка, автор, название, год, язык `rus`, главы с таймкодами.
- Сведение всех разделов в одну дорожку — ручной шаг владельца.

### 5.7 Ручная правка

```
run list NN_<slug> --status bad      # что в очереди
run redo NN_<slug> 0042              # переозвучить кусок
run lock NN_<slug> 0042              # принять вручную, больше не трогать
run assemble NN_<slug>               # пересобрать раздел
```

Ударения правятся через `pronounce.yaml`, а не подменой текста в манифесте.

## 6. Тестирование

**Слой 1** — логика и переносимость, без моделей. Чанкер, хеши, паузы, нормализатор сравнения, применение `read_rules`, `normalize()` цепочки гл. 30, каждое правило нормализации на реальных строках книги, ассерты на кодпоинты и покрытие, resume-логика, greptests на `encoding=`, `os.path.join`, `~/.cache`, `bin/ffmpeg`.

**Слой 2** — чужая ОС на Mac: подменённый `HOME` с проверкой, что туда ничего не записалось; `spawn`; `HF_HUB_OFFLINE=1` с пустым `models/` → внятная ошибка без загрузки; `--device cpu`; прерывание и перезапуск.

**Слой 3** — реальные модели, маркер `slow`, при `RUN_SLOW=1`.

**CI:** `uv sync`, `doctor --no-models`, `pytest -m "not slow"`. Матрицу перевести с `windows-latest` на `ubuntu-latest` — целевая площадка рендера теперь Linux.

Текущее состояние: 80 тестов зелёные.

## 7. Процедура рендера на арендованной машине

1. Локально: `uv sync --extra dev`, `./run.sh doctor`, `pytest`, один раздел собран целиком.
2. `git push` — код, `text/*.txt`, `read_rules.yaml`, `pronounce.yaml`, `config.yaml`.
3. На арендованной машине: `git clone`, `uv sync --extra dev`, веса Qwen скачиваются туда напрямую (2,3 ГБ), референс и латенты копируются отдельно.
4. `doctor`, `bench` — реальный RTF на CUDA.
5. Рендер батчами, результат забирается обратно: `out/sections/` целиком.

**Критерий готовности:** CI зелёный + QC работает + один раздел прошёл слушательский тест.

Референс, веса и рукопись в репозиторий не кладутся.

## 8. Экономика времени

**Книга ≈12,4 часа аудио, 5127 чанков.**

Локально на Mac CPU RTF ≈6 (с термальным троттлингом, число шумное). Для тестов нормально: раздел «Отзывы» (1,5 минуты) считался ~9 минут.

**Ryzen 7 5700X (8 ядер / 16 потоков, 30 ГБ), измерено бенчем (этап E, 10 чанков гл.13, production config, fp32):**

| Раскладка | Throughput | RAM/воркер | Примечание |
|---|---|---|---|
| 1×16 | 0,183 audio-s/wall-s | 6,5 ГБ | один воркер, все ядра |
| **4×4** | **0,258** | **5,7 ГБ** | **лучший; выбран** |
| 4×4 interop=2 | 0,253 | 6,4 ГБ | inter-op не помогает |
| 8×2 | своп | — | 8×5 ГБ > 30 ГБ RAM |

Это **стена памяти, не вычислений**: fp32-веса (~2,5 ГБ) стримятся на каждом шаге через dual-channel RAM; 4 воркера дают лишь +40% к одному. Рычаги снижения footprint проверены и **не работают на Zen 3**: bf16 в 35× медленнее (нет AVX512-BF16, софтверный апкаст), fp16 даёт inf/nan в сэмплинге, int8-dynamic ломает модель (100% runaway, 0 годного аудио). CER fp32 на гл.13: mean 0,016, median 0,006 — качество в норме.

**Полная книга на Ryzen: 12,4 ч × 3600 / 0,258 ≈ 48 часов стены ≈ две ночи.** Принято: стабильный fp32 4×4 предпочтительнее хрупкого быстрого.

На арендованной GPU ожидаемый RTF 0,1–0,3, вся книга за 2–5 часов; хватит самой дешёвой карты с CUDA (0,6B в fp16 ~1,3 ГБ). Запасной путь, требует согласия автора на выгрузку голоса. Площадки: Vast.ai и RunPod дешевле, immers.cloud и Selectel — рубли и без санкционного риска.

## 9. Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| Неверные ударения без RUAccent | Высокая | `pronounce.yaml` + прослушивание 484 заголовков отдельной очередью |
| Клон «плывёт» на длинных разделах | Высокая | Слепой тест на 8–10 слушателях; гибридный сценарий |
| `temperature` 0.9 даёт проглоченные слова | Средняя | QC по CER до массового рендера, не после |
| Ложные срабатывания CER из-за разных нормализаций | Высокая | Общий нормализатор + тесты на реалистичных парах |
| Правка текста обнуляет готовое аудио | Высокая | Выравнивание по хешу, `_orphan/`, флаг `locked` |
| Раздел отдан без мастеринга → клиппинг | Средняя | Сырой выход Qwen на грани FS; `master` обязателен |
| Аренда: голос и текст на чужом сервере | Определённая | Согласовать с автором отдельно от согласия на клонирование |
| Окружение не воспроизведётся на Linux | Средняя | Проверено только на macOS; CI на `ubuntu-latest` до рендера |

**Рекомендуемый сценарий — гибрид:** у автора уже есть 33 минуты собственного чтения первой главы. Поставить его живой голос в начало книги, дальше синтез — снимает главный риск бесплатно.

## Приложение: требования к референсу

Не самый выразительный фрагмент, а самый чистый и ровный: 10–20 секунд, mono, 24 кГц, нейтральная читательская манера, без музыки, эха и придыхания в микрофон.

Установлен кандидат 01 (15 с). Машинный подбор «самого ровного» участка себя не оправдал: выбранный по минимуму вариации энергии кусок дал худший синтез, чем выбранный на слух.

Менять референс после начала массового рендера нельзя: хеши обнулятся, тембр разъедется между готовыми и новыми разделами.
